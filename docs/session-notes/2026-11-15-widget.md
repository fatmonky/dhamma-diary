# Widget: tonight's question (spec 8.4; build step 11)

## What changed

- **New target `DhammaDiaryWidget`** (app extension, bundle ID `com.whitestone.DhammaDiary.Widget`), embedded in the app. One widget, "Tonight's question", in two sizes:
  - Home Screen medium: "TONIGHT · AN 10.51" in robe brown above the question in serif (up to four lines).
  - Lock Screen rectangular: the question alone, up to three lines.
  - Tapping opens `dhammadiary://tonight`, which the app handles by opening Diary → Tonight.
  - Timeline: an entry now and one at the next 03:00, then refresh. The app also reloads widget timelines whenever it becomes active.
  - No stones or journal text on the widget.
- **App Group `group.com.whitestone.DhammaDiary`** on the app and widget (entitlements via `project.yml`). `PassageSequence` now stores the first day in `sharedDefaults` (the group), and `moveFirstDayToSharedStore()` copies an existing value across once at launch.
- The widget compiles the app's `Passage.swift`, `PassageSequence.swift`, `DateHelpers.swift` and `passages.json`, so it works out tonight's passage exactly as the app does. `JournalPassageCopy` moved into `Passage.swift` so that file stands alone.
- The app's URL scheme `dhammadiary` is registered in a generated `DhammaDiary/Info.plist`.
- AGENTS.md lists the widget, the shared files and the week look-back.

## Tests

66/66 pass. New `SharedFirstDayTests` (2): an existing first day is copied once and never overwritten; nothing to copy leaves the shared store empty.

## Checked in the simulator

- The widget extension is built and embedded in the app.
- On PJ's simulator (first day 15 Nov, stored before the App Group), after installing this build, the App Group's preferences hold `sequence.firstDay = 2026-11-15`, so the sequence carries on.

## Not verified

- The widget on screen. Widgets can't be added to the simulator's Home or Lock Screen from the command line. PJ to add it on their phone while dogfooding: long-press the Home Screen → + → Dhamma Diary.
- The 03:00 change and tapping through to Tonight.
- **Device builds:** the App Group must be registered for PJ's team. With automatic signing, Xcode does this the first time the app is built for a device with the team selected. Fastlane/TestFlight will need a provisioning profile that includes the group and the new widget bundle ID.
